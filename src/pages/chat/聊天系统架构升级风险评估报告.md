## 🔍 详细风险分析

### 风险 1: WebSocket 连接管理迁移 🔴 **高风险**

#### 现状分析

**当前架构**:
```typescript
// chat.vue - 页面级连接管理
onShow(() => {
  if (!socketManager.isConnected()) {
    socketManager.connect(token)
  }
  socketManager.on(SocketEvent.NEW_MESSAGE, handleNewMessage)
  // ... 其他监听
})

onUnmounted(() => {
  cleanupWebSocket()
  socketManager.disconnect()  // ⚠️ 页面销毁时断开连接
})
```

**升级后架构**:
```typescript
// App.vue - 应用级连接管理
onLaunch(() => {
  if (userStore.token) {
    socketManager.init(userStore.token)  // 🔄 连接生命周期改变
  }
})

// chat.vue - 只负责数据消费
onShow(() => {
  // ✅ 不再管理连接，只使用 Store 数据
  chatStore.fetchConversations()
})
```

#### 风险点

| 编号 | 风险描述 | 影响 | 发生概率 |
|-----|---------|------|---------|
| 1.1 | **连接时机错误** - token 未准备好时就尝试连接 | 连接失败，用户无法收发消息 | **中** 🟡 |
| 1.2 | **重复连接** - App.vue 和页面同时调用 connect | 资源浪费，可能导致消息重复 | **低** 🟢 |
| 1.3 | **断开时机错误** - 用户登出后连接未断开 | 内存泄漏，安全隐患 | **中** 🟡 |
| 1.4 | **重连失败** - 网络切换时连接丢失 | 用户收不到消息，需要重启应用 | **中** 🟡 |

#### 影响范围
- ✅ **局部影响**: 仅影响聊天模块，不影响其他功能
- ⚠️ **用户体验**: 连接失败会导致消息延迟或丢失

#### 缓解措施

```typescript
// ✅ 解决方案 1: 确保 token 准备好再连接
const initWebSocket = () => {
  const userStore = useUserStore()
  
  // 等待 token 准备好
  const unsubscribe = userStore.$subscribe((mutation, state) => {
    if (state.token && !socketManager.isConnected()) {
      console.log('[App] Token ready, initializing WebSocket')
      socketManager.init(state.token)
      unsubscribe() // 取消订阅，避免重复触发
    }
  })
  
  // 如果已经有 token，立即连接
  if (userStore.token && !socketManager.isConnected()) {
    socketManager.init(userStore.token)
  }
}

// ✅ 解决方案 2: 防止重复连接
// socket.ts
init(token: string) {
  if (this.connected || this.connecting) {
    console.warn('[SocketManager] Already initialized, skipping')
    return
  }
  this.connect(token)
  this.registerGlobalListeners()
}

// ✅ 解决方案 3: 确保登出时断开
userStore.$subscribe((mutation, state) => {
  if (!state.token && socketManager.isConnected()) {
    console.log('[App] User logged out, destroying WebSocket')
    socketManager.destroy()
  }
})

// ✅ 解决方案 4: 增强重连机制
onShow(() => {
  // 从后台回到前台，检查连接状态
  if (userStore.token && !socketManager.isConnected()) {
    console.log('[App] Reconnecting after resume')
    socketManager.init(userStore.token)
  }
})
```

#### 测试计划

- [ ] **场景 1**: 用户登录 → 检查连接是否建立
- [ ] **场景 2**: 切换到后台再回来 → 检查连接是否保持/恢复
- [ ] **场景 3**: 用户登出 → 检查连接是否断开
- [ ] **场景 4**: 网络断开再连接 → 检查自动重连
- [ ] **场景 5**: 多个页面快速切换 → 检查连接是否稳定

### 风险 2: 事件监听器内存泄漏 🟡 **中风险**

#### 现状分析

**当前问题**:
```typescript
// room.vue - 现有代码
onLoad(() => {
  socketManager.on(SocketEvent.NEW_MESSAGE, handleNewMessage)  // ⚠️ 在 onLoad 注册
})

onHide(() => {
  // ❌ 没有移除监听器！
})

onUnmounted(() => {
  socketManager.off(SocketEvent.NEW_MESSAGE, handleNewMessage)  // ⚠️ 页面卸载才移除
})
```

**问题**: 用户在聊天室 A → 返回列表 → 进入聊天室 B → 返回列表 → 重新进入聊天室 A
- ❌ **第一次**: 注册 1 个监听器
- ❌ **第二次**: 又注册 1 个监听器（第一个未移除）
- ❌ **结果**: 消息重复处理 2 次

#### 风险点

| 编号 | 风险描述 | 影响 | 发生概率 |
|-----|---------|------|---------|
| 2.1 | **监听器未移除** - onHide 未清理，导致重复监听 | 消息重复显示，内存泄漏 | **高** 🔴 |
| 2.2 | **全局监听器重复注册** - 多次调用 init() | 全局事件重复触发，性能下降 | **中** 🟡 |
| 2.3 | **页面销毁后仍处理事件** - 监听器引用已销毁的组件 | 运行时错误，闪退 | **低** 🟢 |

#### 影响范围
- ⚠️ **高频操作**: 用户频繁切换聊天室时问题明显
- ⚠️ **性能下降**: 内存占用增加，应用变慢

#### 缓解措施

```typescript
// ✅ 解决方案 1: onShow 注册，onHide 移除（标准模式）
// room.vue
onShow(() => {
  console.log('[Room] 👀 Page shown, joining room and registering listeners')
  
  socketManager.joinConversationRoom(roomId.value)
  
  // 注册页面级监听器
  socketManager.on(SocketEvent.NEW_MESSAGE, handleNewMessage)
  socketManager.on(SocketEvent.TYPING_START, handleTypingStart)
  socketManager.on(SocketEvent.TYPING_STOP, handleTypingStop)
})

onHide(() => {
  console.log('[Room] 😴 Page hidden, leaving room and unregistering listeners')
  
  socketManager.leaveConversationRoom(roomId.value)
  
  // ✅ 关键：移除监听器
  socketManager.off(SocketEvent.NEW_MESSAGE, handleNewMessage)
  socketManager.off(SocketEvent.TYPING_START, handleTypingStart)
  socketManager.off(SocketEvent.TYPING_STOP, handleTypingStop)
})

// ✅ 解决方案 2: 防止全局监听器重复注册
// socket.ts
private globalListenersRegistered = false

registerGlobalListeners() {
  if (this.globalListenersRegistered) {
    console.warn('[SocketManager] Global listeners already registered')
    return
  }
  
  // ... 注册监听器 ...
  
  this.globalListenersRegistered = true
  console.log('[SocketManager] ✅ Global listeners registered')
}

destroy() {
  // ... 清理连接 ...
  
  this.globalListenersRegistered = false  // ✅ 重置标志
}

// ✅ 解决方案 3: 防御性检查（避免引用已销毁的组件）
const handleNewMessage = (data: any) => {
  // 检查组件是否还活着
  if (!roomId.value) {
    console.warn('[Room] Component destroyed, ignoring message')
    return
  }
  
  if (data.room_id !== roomId.value) {
    return
  }
  
  // ... 处理消息 ...
}
```

#### 测试计划

- [ ] **场景 1**: 进入聊天室 A → 返回 → 重新进入 A → 检查消息是否重复
- [ ] **场景 2**: 连续快速切换 5 个聊天室 → 检查内存占用
- [ ] **场景 3**: 发送消息时切换页面 → 检查是否有运行时错误
- [ ] **场景 4**: 使用开发者工具监控事件监听器数量

### 风险 3: 双层房间模型适配 🟡 **中风险**

#### 现状分析

**后端双层模型**:
```
个人房间 (Personal Room):
- 名称: NormalUser_{userId}
- 用途: 接收全局事件（用户状态变化、新消息通知）
- 加入: 后端自动加入（连接时）

会话房间 (Conversation Room):
- 名称: conversation_{roomId}
- 用途: 接收页面级事件（正在输入、消息已读）
- 加入: 前端主动加入（进入聊天室时）
```

**前端现状**:
```typescript
// 现有代码 - 只有一种房间
socketManager.joinRoom(roomId)  // ⚠️ 没有区分房间类型
```

#### 风险点

| 编号 | 风险描述 | 影响 | 发生概率 |
|-----|---------|------|---------|
| 3.1 | **房间类型混淆** - 个人房间和会话房间搞混 | 事件路由错误，收不到消息 | **高** 🔴 |
| 3.2 | **后端未完全实现** - 后端还未支持双层模型 | 升级后功能失效 | **高** 🔴 |
| 3.3 | **事件分发错误** - 全局事件发到会话房间 | 消息重复或丢失 | **中** 🟡 |
| 3.4 | **房间状态不一致** - 重连后会话房间未恢复 | 用户收不到消息 | **中** 🟡 |

#### 影响范围
- 🔴 **核心功能**: 直接影响消息收发
- ⚠️ **依赖后端**: 需要后端配合才能完成升级

#### 缓解措施

```typescript
// ✅ 解决方案 1: 明确区分房间类型
// socket.ts
joinConversationRoom(roomId: number) {
  this.send('join_room', {
    room_id: roomId,
    room_type: 'conversation'  // ✅ 明确标识房间类型
  })
  
  this.conversationRooms.add(roomId)
  console.log(`[SocketManager] 🚪 Joined conversation room: conversation_${roomId}`)
}

// ✅ 解决方案 2: 重连后自动恢复会话房间
private rejoinConversationRooms() {
  if (this.conversationRooms.size === 0) return
  
  console.log('[SocketManager] 🔄 Rejoining conversation rooms after reconnect')
  
  this.conversationRooms.forEach(roomId => {
    this.send('join_room', {
      room_id: roomId,
      room_type: 'conversation'
    })
  })
}

this.socket.on('connect', () => {
  // ... 连接成功后 ...
  this.rejoinConversationRooms()  // ✅ 自动恢复房间
})

// ✅ 解决方案 3: 向后兼容（如果后端未升级）
const USE_DUAL_LAYER_MODEL = true  // 🔧 功能开关

joinConversationRoom(roomId: number) {
  if (USE_DUAL_LAYER_MODEL) {
    this.send('join_room', {
      room_id: roomId,
      room_type: 'conversation'
    })
  } else {
    // 降级方案：使用旧的 join_room
    this.send('join_room', { room_id: roomId })
  }
  
  this.conversationRooms.add(roomId)
}

// ✅ 解决方案 4: 事件路由验证
registerGlobalListeners() {
  // 全局事件：用户状态变化
  this.on(SocketEvent.GLOBAL_USER_STATUS_UPDATE, (data) => {
    console.log('[SocketManager] 🌐 Global event received (from personal room):', data)
    chatStore.updateUserOnlineStatus(data.user_id, data.is_online)
  })
  
  // ⚠️ 不要在这里注册会话房间事件！
  // TYPING_START, MESSAGE_READ 等事件应该在页面级注册
}
```

### 风险 4: ChatStore 状态同步 🟢 **低风险**

#### 现状分析

**升级前**: 页面本地状态
```typescript
// chat.vue
const rooms = ref<ChatRoom[]>([])  // ⚠️ 页面级状态

const handleNewMessage = (data: any) => {
  const roomIndex = rooms.value.findIndex(r => r.id === data.room_id)
  if (roomIndex !== -1) {
    rooms.value[roomIndex].last_message = data.content  // ⚠️ 手动更新
    rooms.value[roomIndex].unread_count++
  }
}
```

**升级后**: 全局状态
```typescript
// store/chat.ts
const chatStore = useChatStore()

// 全局监听器自动更新 Store
socketManager.on(SocketEvent.NEW_MESSAGE_NOTIFY, (data) => {
  chatStore.updateConversationItem(data)  // ✅ Store 自动更新
})

// chat.vue - 只消费数据
const rooms = computed(() => chatStore.sortedConversations)  // ✅ 响应式自动更新 UI
```

#### 风险点

| 编号 | 风险描述 | 影响 | 发生概率 |
|-----|---------|------|---------|
| 4.1 | **Store 未初始化** - 页面比 App.vue 先加载 | Store 数据为空，页面空白 | **低** 🟢 |
| 4.2 | **响应式失效** - 数据更新但 UI 不更新 | 用户看到过期数据 | **低** 🟢 |
| 4.3 | **TabBar 徽标未更新** - 未读数计算错误 | 用户错过消息 | **中** 🟡 |

#### 影响范围
- ✅ **局部影响**: 仅影响会话列表页面
- ✅ **易于回滚**: Store 问题可快速降级

#### 缓解措施

```typescript
// ✅ 解决方案 1: 确保 Store 初始化顺序
// App.vue
onLaunch(() => {
  const userStore = useUserStore()
  const chatStore = useChatStore()  // ✅ 提前初始化 Store
  
  if (userStore.token) {
    socketManager.init(userStore.token)
    chatStore.fetchConversations()  // ✅ 加载初始数据
  }
})

// ✅ 解决方案 2: 页面增加 loading 状态
// chat.vue
const loading = computed(() => chatStore.loading)
const rooms = computed(() => chatStore.sortedConversations)

<view v-if="loading && rooms.length === 0">加载中...</view>
<view v-else-if="rooms.length === 0">暂无会话</view>

// ✅ 解决方案 3: 响应式更新最佳实践
// store/chat.ts
updateConversationItem(update: ConversationUpdate) {
  const conversation = this.conversations.find(c => c.id === update.roomId)
  
  if (conversation) {
    // ✅ 直接修改属性（Vue 3 响应式会自动追踪）
    conversation.last_message = update.latestMessage
    conversation.last_message_time = update.timestamp
    conversation.unread_count = update.unreadCount
    
    // ✅ 重新排序（触发 computed 更新）
    this.conversations.sort((a, b) => {
      return new Date(b.updated_at).getTime() - new Date(a.updated_at).getTime()
    })
  }
  
  this.updateTotalUnreadCount()  // ✅ 更新 TabBar
}

// ✅ 解决方案 4: TabBar 徽标自动更新
updateTotalUnreadCount() {
  this.totalUnreadCount = this.conversations.reduce(
    (sum, conv) => sum + (conv.unread_count || 0),
    0
  )
  
  // ✅ 自动更新 TabBar 徽标
  if (this.totalUnreadCount > 0) {
    uni.setTabBarBadge({
      index: 1,  // 🔧 根据实际 TabBar 配置调整
      text: this.totalUnreadCount > 99 ? '99+' : String(this.totalUnreadCount)
    })
  } else {
    uni.removeTabBarBadge({ index: 1 })
  }
}
```
